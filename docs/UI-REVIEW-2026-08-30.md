# UI Review — 2026-08-30

updated 2026-08-30 program/ui-unification

## Root cause

`index.html` has `layout: null` and is fully self-contained: its own `<head>`, its own
nav/header/footer, and its own stylesheet `assets/css/portfolio-rewrite.css`. Every other
page uses `_layouts/default.html`, which pulls `assets/css/components/theme.css` (design
tokens) plus `assets/css/style.css` (compiled from `assets/css/style.scss`). Two
independent CSS systems, two independent palettes, two navs — hence the identity switch on
first click. `assets/css/components/*.css` (base, buttons, hero, navigation, timeline,
etc.) and `assets/css/custom.css` / `styles.css` are not linked from any template or
include — dead weight, out of scope for this pass.

## Pillar findings

**Hierarchy.** Editorial system (index.html) uses scale + weight (Arial Black display,
clamp'd to 8vw+) and hairline rules to carry hierarchy. Inner-page system used `h1` at a
flat `clamp(2rem,4vw,2.7rem)` with no display-face distinction from `h2`/`h3` — everything
reads as "generic SaaS docs," no editorial voice.

**Consistency.** Confirmed split-brain above. Additionally, `experience.md` renders
`.timeline-technologies`, `.timeline-tech`, `.timeline-description`, `.education-*`,
`.animate-on-scroll` — none of which exist in the live `style.scss`; the classes were
written against the dead `components/experience.css`, so the experience page currently
renders those blocks completely unstyled (browser defaults).

**Spacing.** Editorial system runs on a bordered-grid rhythm (hairline dividers, no
shadows). Inner-page system runs on card+shadow rhythm (`--shadow`, `--radius:14px`).
Kept post-unification: cards are retained (they're the right container for prose+CTA
content at this density) but re-skinned to hairline borders and near-zero radius so they
read as one family with the editorial cards on the homepage.

**Type.** Inner pages used system UI stack for both body and headings — no display face,
no mono small-caps labels. `--display`/`--mono` from `portfolio-rewrite.css` were promoted
into the shared `theme.css` token file so every page draws from one definition.

**Color.** Inner-page palette was indigo/violet (`--accent:#4f46e5`, `--accent-2:#7c3aed`)
over a white/navy-tinted surface — a stock "AI purple" SaaS look, unrelated to the
homepage's cream/ink/orange system. Replaced token values in `theme.css` with the
editorial hex values (ink `#171715`, paper `#f5f1e8`, signal `#ff5a36`, lime `#c9ff63`).
Same var names (`--bg`, `--text`, `--accent`, …) are kept so every consuming rule in
`style.scss` repaints without a rename sweep. Dark mode (`html[data-theme="dark"]`) was
redefined to an ink-based editorial-dark palette instead of the old navy-dark.

**Responsiveness.** Homepage hero used `clamp(3.2rem, 8.2vw, 8.3rem)` — verified clipping
around 800px width. Clamped to the range specified by the owner. Stat sidebar already
collapses to single column under 980px via existing media query; verified it does not wrap
awkwardly at 375px after the type-scale change.

## Known duplication accepted, not fixed

`portfolio-rewrite.css` keeps its own literal `:root` copy of the editorial color/type
tokens (index.html is intentionally standalone and out of scope for a `layout: null`
rewrite). `theme.css` is the second, canonical source for every other page. Two sources,
kept numerically identical by hand for this pass — true single-sourcing would mean folding
index.html into the shared layout, which is a rewrite this task explicitly excluded.
