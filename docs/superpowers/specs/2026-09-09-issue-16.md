# Scenario-based opportunity routing Implementation Plan

> **For agentic workers:** Use Superpowers executing-plans after the proposed design is accepted. Track actual work with checkboxes; keep builder and reviewer roles separate.

**Goal:** Preserve the reason visitors came to Suleman while turning suitable conversations into Viyu engagements, professional opportunities for Suleman, or personal projects.
**Architecture:** A short static contact page with scenario-specific links to the already published contact channel. Move the existing optional personal workshop form to its own route so it is not the default path for every visitor. Do not build a new CRM or qualification engine.
**Tech stack:** Existing Jekyll, Markdown/Liquid, current JavaScript form client and Python checks.
**Spec:** Parent #11 and this issue's owner-directed revision dated 2026-09-09.

## What changed

This replaces the earlier plan to move a generic Viyu paragraph above the personal form. The owner explicitly rejected that framing: he is the Sr. Services Engineer whose expertise attracts visitors, and the site should create appropriate opportunities for both him and Viyu. The old home/hobby-only interpretation does not describe every opportunity for Suleman.

The visitor should start with their situation. Provider, participants and scope become clear without making the visitor classify themselves as “business-grade.”
